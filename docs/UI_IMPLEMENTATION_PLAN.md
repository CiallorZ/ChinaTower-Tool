# LinkForge UI 分阶段实施计划

日期：2026-10-15
依据：`LinkForge_UI_Design_Guidelines_V1.1.md` §11 推荐顺序、`CODEX_TASKS.md` 任务拆解
原则：先建立设计系统与可复用组件，再逐页改造业务页面；每阶段独立可构建、可验证、可回滚。

> 通用红线（适用于每个阶段）：不做纯静态样式；不用假数据伪装真实功能；不删减 PRD 模块；长任务不阻塞 UI 线程且提供取消；凭据在日志/历史/复制/报告中默认脱敏；阶段结束必须真实执行构建与测试并报告结果。

## 阶段 01：设计令牌

**状态**：已完成（2026-10-15）。实际交付与验证结果见 `BUILD_LOG.md`「阶段 01」章节；
实施期间发现 7 个真实缺陷（含深色主题只切换部分元素、按钮悬停态不可读），
已修复并沉淀为 ADR-017、ADR-018 与自动化守卫测试。

**目标**：把规范 §2.2 的令牌值落为可切换的资源字典，成为后续所有视觉的唯一来源。


**改动文件（预计）**

| 文件 | 动作 |
| --- | --- |
| `src/LinkForge.App/Themes/Tokens/Palette.Light.xaml` | 新增：浅色原始色值 |
| `src/LinkForge.App/Themes/Tokens/Palette.Dark.xaml` | 新增：深色原始色值（独立定义，非反色） |
| `src/LinkForge.App/Themes/Tokens/Semantic.xaml` | 新增：语义令牌（`LfColorTextPrimary` 等） |
| `src/LinkForge.App/Themes/Tokens/Dimensions.xaml` | 新增：间距、圆角、字号、控件高度、导航宽度 |
| `src/LinkForge.App/Themes/ThemeResources.xaml` | 新增：合并入口 |
| `src/LinkForge.App/App.xaml` | 修改：引用令牌入口 |
| `tests/LinkForge.Application.Tests/` | 新增：令牌完整性与键名一致性测试 |

**实现要点**

- 语义令牌名与规范 §2.2 表格逐条对应，禁止业务代码直接写 `#2563EB`。
- 深色主题单独取值，不复用浅色值做取反。
- 提供令牌键集合的自动化测试：浅色与深色必须暴露同一组键，避免切换主题时缺键。

**风险**

- WPF-UI 自带资源键可能与语义键同名，统一加 `Lf` 前缀规避。
- 深色对比度不达标，阶段 06 做对比度核验。

**验证方式**

- `dotnet build` 通过；`dotnet test` 中令牌键一致性测试通过。
- 人工：临时切换浅/深色，确认主窗口与示例控件无缺色、无不可读文本。

**实际交付（与计划的差异）**

| 项 | 计划 | 实际 |
| --- | --- | --- |
| 令牌文件 | 4 个 | 5 个（新增 `ControlMapping` 内容并入调色板，见 ADR-018） |
| 组合边距 | 未预见 | 新增 11 个完整 `Thickness` 令牌（WPF 不允许 `{StaticResource X},0`） |
| 引用方式 | 未预见 | 颜色令牌必须用 `DynamicResource`（ADR-017），并加静态守卫测试 |
| 控件库映射 | 未预见 | 需映射 WPF-UI `Button*` / `AccentButton*` 资源键（ADR-018） |
| 验证 | 构建 + 令牌键一致性 | 构建（`-warnaserror`）+ 38 个测试 + 真实启动截图（浅/深两套） |
| 新增测试项目 | 计划并入 Application.Tests | 独立 `LinkForge.App.Tests`（net10.0-windows，31 个测试） |

## 阶段 03：应用壳层

**状态**：已完成（2026-10-16）。实际交付与验证结果见 `BUILD_LOG.md`「阶段 03」章节；
实施期间发现并修复 11 个真实缺陷，沉淀为 ADR-021 / ADR-022 / ADR-023。

**目标**：完成规范 §3.1、§3.2 的窗口结构、导航、页面容器与主题切换。


**改动文件（预计）**

| 文件 | 动作 |
| --- | --- |
| `Views/ShellWindow.xaml` | 新增：FluentWindow 主窗口（标题栏 + 导航 + 内容 + 底部面板） |
| `ViewModels/ShellViewModel.cs` | 新增：导航状态、项目/环境上下文、面板开合 |
| `Navigation/NavigationService.cs` | 新增：页面注册与导航 |
| `Services/ThemeService.cs` | 新增：浅/深/跟随系统 + 持久化 |
| `Services/AppSettingsStore.cs` | 新增：用户级设置持久化（面板状态、主题、导航折叠） |
| `Views/Pages/*` | 新增：各模块占位页（明确标注"尚未实现"，不伪造功能） |
| `Resources/Strings/*.xaml` | 新增：文案集中管理 |
| `App.xaml.cs` | 修改：DI 容器接线 |

**实现要点**

- 一级导航采用 FUNCTION_TREE 结构（见 `REVIEW_V1.0.md` C-01 裁决）。
- 导航项：图标 + 文本 + 选中态（背景/指示线/字重），折叠模式保留 ToolTip。
- 页面切换不得取消正在运行的任务。
- 未实现模块的占位页必须显示"依赖缺失/尚未实现"状态，而非空白或假数据。
- 布局用 Grid/DockPanel/ItemsControl，禁止 Canvas 绝对定位。

**风险**

- WPF-UI `NavigationView` 与自定义标题栏的视觉耦合，先做最小可用版本再调优。
- 主题切换与令牌字典合并顺序冲突，固定合并顺序并写测试。

**验证方式**

- 构建 + 测试通过。
- 人工：1366×768 与 1920×1080 下导航可用、关键按钮不被裁切；Tab 顺序合理；主题切换立即生效且重启后保持。

**实际交付（与计划的差异）**

| 项 | 计划 | 实际 | 理由 |
| --- | --- | --- | --- |
| `Navigation/NavigationService.cs` | 新增 | **未创建**，改为 `Navigation/NavigationCatalog.cs` + `ShellViewModel.NavigateTo` | 当前只有"按功能树切换内容区"一种导航行为，没有多页面栈、返回栈或参数传递。先建 `NavigationService` 会得到一个只有一次调用的抽象。阶段 05 各业务页需要带参数跳转时再引入，届时接口有真实约束可依 |
| `Services/ThemeService.cs` | 新增 | **未创建**，主题能力并入既有 `Services/ThemeManager.cs` | 阶段 01 已有 `ThemeManager`（解析偏好、替换调色板）。计划中的 `ThemeService` 与它职责重叠，另起一个类会出现"两处都能切主题"。本阶段只在其上补 `SyncWithWpfUiTheme()` 与持久化调用 |
| `Resources/Strings/*.xaml` | 新增文案集中管理 | **未创建** | 现阶段文案均为单处使用的界面标签，抽成资源字典只是把字面量换个位置。多语言需求出现时再引入，避免过早抽象 |
| `Views/Pages/*` 占位页 | 每模块一个占位页 | 改为**一个共用占位区**，由 `ShellViewModel.IsCurrentModuleImplemented` 驱动 | 12 个模块各写一个只有标题的空页面，等于 12 份重复 XAML。共用占位区同样满足"未实现必须明确标注、不得空白或假数据"，且删掉了重复 |
| 主题切换 | 浅/深/跟随系统 | 一致，另需**回灌令牌**（ADR-021） | 计划未预见控件库会自行改主题 |
| 图标 | 计划未单列 | 新增 `LfGlyph.cs` 集中管理 + `GlyphTests` 双字体码位校验（ADR-022） | 计划未预见两套字体码表不通用，会渲染出豆腐块 |
| 截图验证 | 计划未单列 | 新增"两主题必须不同"断言 + 固定窗口位置 + 关闭并行（ADR-023） | 计划未预见阶段 02 的截图证据实际无效 |
| 测试规模 | 未预估 | App 测试从 179 增至 257（净增 78） | 壳层引入的交互与持久化路径都需要回归守卫 |

## 阶段 05：业务页面

**目标**：按统一模板逐页实现，顺序按 PRD 优先级：网络基础 → HTTP/API → MQTT → RTSP → 其余。

**每页必须包含**（规范 §4.2）

1. 标题 + 一句话用途
2. 目标/连接参数区（含字段级校验）
3. 可折叠高级选项
4. 明确主操作（运行中变为停止）
5. 运行状态区（阶段 + 耗时 + 取消）
6. 结构化结果区（结论先于原始日志）
7. 原始输出/日志（可展开）
8. 导出/复制/生成报告（按已实现能力显示）

**各页关键约束**

| 页面 | 关键约束 |
| --- | --- |
| 网络诊断 | ICMP 无响应不得断言主机离线；扫描范围可见、默认最小、可取消、需授权确认 |
| API 调试 | 敏感 Header 在历史与导出中默认脱敏；大响应截断提示；不关闭 TLS 校验 |
| MQTT | 断线后状态必须立即变更；消息列表虚拟化；硬件缺失与功能未实现区分显示 |
| 视频/RTSP | URL 密码脱敏；阶段化结果；未实现解码时不放假预览 |
| 安全检测 | 风险等级文字 + 颜色；高风险动作二次确认并描述目标与影响 |
| 任务与报告 | 状态区分"部分成功"；报告区分事实与建议；导出反馈保存位置 |

**风险**

- 各页并发开发易产生样式漂移，每页完成后必须复核"无硬编码视觉值、无重复组件"。
- 协议实现复杂度，每页独立提交，失败可单独回滚。

**验证方式**

- 每页：构建 + 该模块单元/集成测试 + 人工走查七类状态。
- 协议测试使用本地 mock 或容器（Docker 已可用），不依赖公网。

### LF-007 HTTP/API 工作台交付记录

**状态**：已完成（2026-10-21）。

**已交付**

- `Adapters.Http`：GET/POST/PUT/PATCH/DELETE，Query、Headers、JSON/文本/表单 Body，
  Basic/Bearer/API Key，认证字段不进入 URL。
- 请求选项：1–300 秒超时、0–10 次重定向、跟随/不跟随；TLS 证书验证始终启用。
- 响应：状态码/原因、响应头、响应体、耗时、响应字节数；超过上限时明确提示截断。
- 失败语义：DNS、连接、TLS、超时、非法请求分别给出可操作建议；
  4xx/5xx 是完整 HTTP 响应，不归类为传输失败。
- 环境变量 `{{name}}`；未定义变量显示字段错误，不发请求。
- 请求历史最多 100 条，认证字段不写入；URL、Header、Body、日志、复制和 JSON 导出统一脱敏。
- 导航：API 工作台从占位状态切换为可用页面。

**验证**

- 全解决方案构建与测试通过（结果见 `BUILD_LOG.md`）。
- HTTP 适配器测试使用本地 mock server，覆盖方法/参数/认证、重定向、4xx/5xx、
  截断、超时、取消、URL userinfo 拒绝与 TLS 源码守卫。
- 页面测试覆盖 1366×768 布局、空/结果状态、浅深色截图差异；
  Shell 测试覆盖 API 页显示与工作台/网络页互斥。
- 应用真实启动/关闭成功，退出码 0。

**明确未交付**
