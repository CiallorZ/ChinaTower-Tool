# Codex 开发任务拆解与执行规约

## 0. 给 Codex 的总指令（先阅读）

你正在开发 LinkForge：Windows 桌面视联网全链路调试工具箱。严格遵守以下约束：

1. 先检查仓库现状和现有约定；不要未经检查就覆盖已有代码。
2. 先实现可构建的纵向切片，不要一次性生成所有模块。
3. 技术基线：C#/.NET + WPF + MVVM；核心业务与 UI 分离。
4. 所有网络/文件/进程操作必须异步，支持 CancellationToken；UI 线程不做阻塞 I/O。
5. 统一诊断状态：Passed、Failed、Warning、Skipped、Unknown、Cancelled、TimedOut。
6. 凭据不得明文写日志、报告或普通项目配置；默认脱敏。
7. 外部进程调用不得拼接 shell 命令；使用参数数组、固定可执行路径、超时与退出码处理。
8. 不实现未经授权的扫描、口令爆破、隐蔽操作或破坏性设备操作。
9. 每个任务必须包含：范围、文件/模块、实现步骤、验收标准、测试。
10. 每个阶段完成后运行构建和测试，报告实际结果；不得声称未运行的测试已通过。
11. 对外部依赖记录版本、许可证、用途和替代方案。
12. 若需求不明确，先列出假设并选择最小安全实现，不要引入无必要的框架。

## 1. 建议执行顺序

### LF-000：仓库勘察与技术决策
目标：确认现状，形成 ADR。
任务：
- 检查仓库、SDK、目标框架、现有 UI 和构建流程。
- 记录 Windows 最低版本、x64 目标、打包方案的待决项。
- 创建 `docs/DECISIONS.md`，记录 WPF、持久化、日志、依赖隔离决策。
验收：
- 不修改业务逻辑；输出目录树和风险清单。
- 所有待决技术选型有负责人/决策期限。

### LF-001：解决方案骨架与 CI
创建：
- `src/LinkForge.App`
- `src/LinkForge.Application`
- `src/LinkForge.Domain`
- `src/LinkForge.Infrastructure`
- `src/LinkForge.Plugin.Abstractions`
- `tests/LinkForge.Domain.Tests`
- `tests/LinkForge.Application.Tests`
- `docs/`
任务：
- 建立依赖方向：App→Application/Infrastructure；Application→Domain/抽象；Domain 不依赖 UI。
- 配置 nullable、可分析器、格式化和测试。
- 加入 README、构建脚本和 CI 示例。
验收：
- 干净环境可 restore/build/test。
- Domain 不引用 WPF。
- 初始测试通过。

### LF-002：设计系统与主窗口
任务：
- 建立主导航、顶部项目/环境栏、中央工作区、底部任务/日志抽屉。
- 建立颜色、字体、间距、状态标签等设计 Token。
- 实现浅色/深色切换与高 DPI 基础适配。
- 用 ViewModel 驱动导航；避免业务逻辑放在 code-behind。
验收：
- 页面无横向溢出；窗口缩放正常。
- 状态标签有文字而非仅颜色。
- 导航可通过键盘操作，基础可访问性检查通过。

### LF-003：统一领域模型与任务框架
任务：
- 建立 Project、EnvironmentProfile、Asset、DiagnosticRun、DiagnosticStep、EvidenceArtifact。
- 实现统一状态枚举、进度事件、取消、超时和异常映射。
- 实现 `IDiagnosticAdapter` 契约和示例 FakeAdapter。
验收：
- 单元测试覆盖状态转换、取消、超时、依赖步骤跳过。
- UI 能显示模拟任务的进度、步骤和结果。
- 任何未执行步骤不误报为 Failed。

### LF-004：项目持久化与资产管理
任务：
- SQLite 仓储、schema 版本、迁移/备份。
- 项目 CRUD、环境配置、资产 CRUD、CSV 导入导出。
- 项目导出默认排除秘密，仅导出 SecretReference。
验收：
- 重启后数据可恢复。
- CSV 无效行给出行号和原因，不造成部分静默丢失。
- 项目文件写入采用原子保存或事务策略。
- 导出文件不包含测试用秘密明文。

### LF-005：结构化日志与脱敏
任务：
- 统一日志字段：Timestamp、Level、Module、RunId、TargetId、EventId。
- 在写入前执行密码、Token、Cookie、Authorization、URL userinfo 脱敏。
- 日志面板支持过滤、搜索、复制、导出。
验收：
- 自动化测试覆盖常见敏感字段与嵌套 JSON。
- UI、磁盘日志、报告三条路径均通过脱敏测试。
- 原始异常详情仅在明确安全边界内提供。

### LF-006：网络基础适配器
任务：
- Ping/ICMP、TCP 连接、DNS 查询、本机网卡/路由信息、Traceroute。
- 统一超时、取消、状态与耗时。
- 采用 ProcessStartInfo.ArgumentList 或原生 API，禁止 shell 字符串拼接。
验收：
- 测试成功、拒绝、超时、DNS 不存在、取消等情形。
- ICMP 被阻断时提示“ICMP 无响应，不能单独证明主机不可达”。
- Traceroute 不可用时给出平台限制说明。

### LF-007：HTTP/API 工作台
任务：
- 请求方法、URL、Query、Headers、JSON/文本 Body。
- 响应状态、Headers、Body、总耗时与异常分类。
- 环境变量与请求历史；默认脱敏。
验收：
- 支持取消、超时、重定向策略可配置。
- 不关闭 TLS 证书验证来“解决”错误。
- 大响应有大小上限/截断提示。
- 集成测试使用本地 mock server，不依赖公网。

### LF-008：MQTT 基础调试器
任务：
- 评估并记录客户端库、版本、许可证。
- 实现连接、断开、订阅、发布、消息流、连接状态。
- TLS 证书校验默认启用；凭据引用安全存储。
- 实现消息筛选、暂停显示、JSON/CSV 导出。
验收：
- 使用本地测试 Broker 或容器测试环境完成集成测试。
- 覆盖断线、超时、认证失败、订阅失败和取消。
- 断线状态不得继续显示为已连接。

### LF-009：RTSP 分阶段诊断
任务：
- 解析并安全展示 RTSP URL；密码永不进入日志。
- 分阶段执行 DNS/TCP/RTSP 握手/鉴权/SDP；媒体接收和解码按组件能力实现。
- 明确区分 Failed、Skipped、Unknown。
- 将播放引擎放入独立抽象，不把 UI 与具体解码库绑定。
验收：
- 使用可控测试服务器或固定样例验证成功、认证失败、超时、无效 SDP。
- 对未实现的 RTP/解码能力明确标为 Not Supported/Skipped，不伪造结果。
- 报告与日志中的 RTSP URL 已脱敏。

### LF-010：报告服务
任务：
- 生成离线 HTML 报告，包含项目、目标、版本、时间、步骤、状态、证据与建议。
- 使用模板，避免将未转义外部数据直接注入 HTML。
- 生成前执行敏感信息扫描。
验收：
- 报告离线可打开；中文显示正常。
- 注入 HTML/脚本样例被正确转义。
- 报告与原始任务结果一致，包含生成时间与脱敏说明。

### LF-011：通用开发者工具
任务：
- JSON 格式化/校验、URL 编码、Base64、时间戳、UUID。
- JWT 仅解码展示，醒目标明未验证签名。
验收：
- 单元测试覆盖 Unicode、无效输入、边界时间戳。
- 大输入有合理限制，不阻塞 UI。

### LF-012：插件和原生 SDK 隔离
任务：
- 定义插件清单、API 版本、能力声明和兼容性检查。
- 先实现内置适配器；再定义进程外适配协议。
- 海康/大华 SDK 先验证许可、位数、依赖、设备覆盖和分发要求。
验收：
- 插件版本不兼容时阻止加载并解释原因。
- 插件崩溃不导致主 UI 进程崩溃。
- 插件不能直接读取宿主秘密库。

### LF-013：集成测试、打包与发布
任务：
- 端到端验证：新建项目→添加资产→运行诊断→查看日志→导出报告。
- 依赖与许可证清单、SBOM、版本信息、安装包签名策略。
- 安装/卸载、升级失败恢复和日志清理测试。
验收：
- 从干净 checkout 可重复构建。
- 生成可追溯版本号、变更日志、依赖清单。
- 发布包在目标 Windows 版本上完成安装验收。

## 4. Definition of Done（每个任务必须满足）
- 功能符合明确验收标准。
- 构建成功；相关测试实际执行并报告结果。
- 失败、取消、超时、无权限、依赖缺失都有明确处理。
- 无凭据明文写入日志/报告/项目导出。
- UI 不阻塞；长任务可取消。
- 文档、配置示例和变更记录同步更新。
- 没有把未实现能力伪装成成功。
