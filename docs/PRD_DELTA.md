# PRD 修订建议（V1.0 → V1.1）

日期：2026-10-15
说明：本文件汇集实施过程中发现的、需要回写 PRD 的条目。**在用户确认前不修改 `PRD.md` 原文。**

## 建议纳入 V1.1 的条目

### PD-01 状态模型分层（对应 ADR-016）

**现状**：PRD §3.7 与 `ARCHITECTURE.md` §3.2 定义了步骤级 7 态（`Passed / Failed / Warning / Skipped / Unknown / Cancelled / TimedOut`）；UI 规范 §4.8 定义了任务级状态（待运行 / 准备中 / 运行中 / 已完成 / 部分成功 / 失败 / 已取消）。

**建议**：在 PRD 中明确"任务层状态"与"步骤层状态"两个独立枚举，并给出映射规则：

- 全部步骤 `Passed` → 任务"已完成"
- 存在 `Passed` 与 `Failed`/`TimedOut` 混合 → 任务"部分成功"
- 存在 `Skipped` → 不计入失败，但需在结论中说明跳过原因
- `Unknown` 不得归入"已完成"

**理由**：避免实现阶段把两层语义混用，导致"未检测"被渲染为"失败"或"部分成功"被吞成"失败"。

### PD-02 默认主题（对应 ADR-014）

**现状**：`UI_WIREFRAMES.md` §10 建议"深色为默认候选主题"；UI 规范 §2.1 要求"跟随系统主题作为默认设置，浅色为主体基调"。

**建议**：在 PRD 中明确默认主题策略为"跟随系统"，并说明浅色为设计基准、深色为完整对等主题。

**理由**：消除线框与 UI 规范之间的表述差异。

### PD-03 一级导航结构（对应 C-01 裁决）

**现状**：`FUNCTION_TREE.md` 与 UI 规范 §3.2 的一级导航命名不一致。

**建议**：以 `FUNCTION_TREE.md` 为准，明确一级导航为：工作台、设备与资产、接入调试、网络诊断、诊断中心、安全中心、开发者工具、项目与报告、设置；并把"视频接入 / IoT 接入 / API 调试"定义为"接入调试"的二级项。

### PD-04 未实现能力的统一表达

**现状**：PRD §1.4 提出"不伪装能力"，但未定义统一表达方式。

**建议**：补充三类状态的固定文案与视觉规范：

- 功能未实现：`尚未实现`（中性色 + 说明 + 计划版本）
- 环境依赖缺失：`依赖缺失`（警告色 + 缺失项 + 获取方式）
- 当前环境不可用：`当前环境不可用`（警告色 + 原因）

**理由**：UI 规范 §4.4、§5.6 要求区分这些状态，但 PRD 未给出词表。

### PD-05 阶段 01 前置的 SDK 基线

**现状**：PRD 未记录开发环境基线。

**建议**：补充"开发与构建基线"章节：.NET SDK 10.0.402（用户级安装）、目标框架 `net10.0-windows`、WPF、x64、Windows 10/11。

**理由**：当前机器初始无 SDK，基线写入 PRD 可避免后续环境歧义。
