# LinkForge 开发与验证规范

日期：2026-10-15
适用范围：`linkforge/` 全部代码
关系：本文件是 `CODEX_TASKS.md` §4（Definition of Done）与 UI 规范 §10、§12 的工程化落地。

---

## 1. 架构与依赖规则

1. 依赖方向固定为 `App → Application → Domain`；`App → Plugin.Abstractions`。Domain 不得引用 WPF、EF Core、Serilog 或任何 I/O 库。
2. 业务逻辑不得写在 View 的 code-behind；View 只做呈现与输入转发。
3. 新增第三方依赖前必须说明：用途、版本、许可证、替代方案，并登记到 `DECISIONS.md` 第 13 节。
4. 不引入第二套 UI 框架；控件样式优先复用 WPF-UI，其次在 `Themes/` 内扩展。
5. 不擅自改动 `PRD.md`、`FUNCTION_TREE.md`、`ARCHITECTURE.md` 的功能边界；需变更时先写 `PRD_DELTA.md`。

## 2. 异步、取消与超时

1. 所有网络、文件、进程、媒体操作必须 `async`，并接收 `CancellationToken`。
2. UI 线程禁止执行阻塞 I/O、DNS 解析、扫描、SDK 阻塞调用。
3. 每个长任务必须提供取消入口，并在取消后及时释放连接与句柄。
4. 每个任务必须定义超时，超时映射为 `TimedOut`，不得与 `Failed` 混用。
5. 任务结束状态必须是终态之一：`Passed / Failed / Warning / Skipped / Unknown / Cancelled / TimedOut`。
6. 未执行的步骤标记为 `Skipped`；禁止把 `Skipped` 或 `Unknown` 显示为失败。

## 3. 状态模型与显示

1. 任务层状态（含"部分成功"）与步骤层状态（7 态）分层存在，映射函数必须可单元测试。
2. 状态表达不得仅依赖颜色，必须同时有图标或文字。
3. 页面必须覆盖适用状态：空、加载、运行、成功、部分成功、失败、取消、依赖缺失。
4. "功能未实现"、"当前环境不可用"、"检测失败"、"用户取消"必须使用不同文案与不同状态，不得混用。

## 4. 凭据与脱敏

1. 密码、Token、Cookie、`Authorization`、API Key、私钥、含凭据 URL 默认遮蔽。
2. 脱敏必须在写入前执行，且 UI、磁盘日志、剪贴板、历史记录、报告、导出共用同一实现。
3. 禁止把密码放入命令行参数。
4. 项目导出默认不含秘密；显式包含时二次确认。
5. 禁止在源码、测试夹具、示例配置、文档中出现真实凭据。
6. 若命令输出意外包含秘密，后续回复中不得重复该值。

## 5. 外部进程与命令

1. 一律使用 `ProcessStartInfo.ArgumentList`（或等价参数数组），禁止 `cmd.exe /c` 拼接用户输入。
2. 固定可执行路径或白名单解析；限定超时；捕获退出码与 stdout/stderr；记录工具版本。
3. 用户输入进入参数前必须做类型与范围校验。

## 6. 视觉实现

1. 业务页面禁止硬编码颜色、字号、`Margin`、`CornerRadius`；一律引用语义令牌。
2. 语义令牌加 `Lf` 前缀，避免与控件库资源键冲突。
3. 布局使用 Grid/DockPanel/ItemsControl 与相对尺寸；禁止用 Canvas 绝对定位搭整页。
4. 大列表（日志、消息、资产）必须启用虚拟化。
5. 图标按钮必须有 `ToolTip` 与可访问名称。
6. 设计时数据与真实数据必须物理隔离；生产路径不得显示样例数据。

## 7. 文案

1. 默认简体中文；协议字段、命令、错误码保留必要英文。
2. 按钮使用明确动词（"开始检测""发送请求"），避免"确定""执行"这类无上下文词。
3. 文案集中管理，不散落在代码里，便于后续本地化。
4. 错误信息必须包含：可读原因 + 错误码/原始信息 + 下一步建议。

## 8. 测试要求

1. 新增或修改逻辑必须补测试；测试与实现同批提交。
2. 单元测试覆盖：状态转换、取消、超时、依赖跳过、脱敏、边界输入（Unicode/空/超大）。
3. 集成测试使用本地 mock 或容器（Docker 可用），不依赖公网与真实设备。
4. 测试失败必须如实报告；不得跳过、不得注释掉失败用例来"通过"。

## 9. 每阶段验证流程

```powershell
# 1. 还原与构建
& "$env:USERPROFILE\.dotnet\dotnet.exe" build LinkForge.slnx -c Debug

# 2. 运行全部测试
& "$env:USERPROFILE\.dotnet\dotnet.exe" test LinkForge.slnx -c Debug --no-build

# 3. 发布前 Release 构建
& "$env:USERPROFILE\.dotnet\dotnet.exe" build LinkForge.slnx -c Release
```

阶段结束必须报告：实际执行的命令 + 真实结果（含失败项）。禁止声称未运行的测试已通过。

## 10. 完成定义（DoD）

- [ ] 功能符合该任务验收标准
- [ ] 构建成功，相关测试实际执行并报告结果
- [ ] 失败、取消、超时、无权限、依赖缺失均有明确处理
- [ ] 无凭据明文进入日志、报告、导出、剪贴板
- [ ] UI 不阻塞，长任务可取消
- [ ] 无硬编码视觉令牌，无重复组件
- [ ] 未实现能力标注为未实现或不可用，不伪装成功
- [ ] 文档、配置示例同步更新

## 11. 变更管理

1. 每个阶段独立提交；阶段 05 每页一次提交。
2. 提交前检查：无多余文件、无秘密、无调试代码、无生成物。
3. 不丢弃他人未提交的改动。
4. 非平凡变更需提供回滚步骤。
5. 工作区当前不是 Git 仓库；在 `git init` 之前，改动以文件级备份与差异清单记录。
