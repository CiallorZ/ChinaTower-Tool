### 4.3 规范内部冲突与裁决（需用户确认）

按规范 §0 的优先级（既有产品需求 > 规范交互规则 > 视觉细节），裁决如下：

**C-01 一级导航命名与数量（重要）**

- `FUNCTION_TREE.md` / `UI_WIREFRAMES.md`：工作台、设备与资产、接入调试（视频/MQTT/HTTP/TCP-UDP）、网络诊断、诊断中心、安全中心、开发者工具、项目与报告、设置。
- 规范 §3.2 推荐：工作台、视频接入、IoT 接入、网络诊断、API 调试、安全检测、数据中心、常用工具、任务与报告、项目管理、设置。
- 裁决：采用 FUNCTION_TREE 结构（一级：工作台 / 设备与资产 / 接入调试 / 网络诊断 / 诊断中心 / 安全中心 / 开发者工具 / 项目与报告 / 设置），把规范推荐的"视频接入 / IoT 接入 / API 调试"作为"接入调试"下的二级项。理由：功能树属"既有产品需求"，优先级高于规范推荐命名；且规范自身明确"一级导航数量与名称以现有功能树为准"。

**C-02 默认主题**

- `UI_WIREFRAMES.md` §10："深色为默认候选主题"。
- 规范 §2.1："主体使用浅色主题，提供完整深色主题；跟随系统主题作为默认设置"。
- 裁决：采用规范——默认"跟随系统"，浅色为主体基调，深色为完整对等主题。理由：线框原文是"候选"（非承诺），且规范为 UI 强约束且版本更新。已记录为 ADR-014。

**C-03 视频预览是否在 MVP 出现**

- `FUNCTION_TREE.md`：P0 只承诺 RTSP 阶段诊断，播放需依赖媒体组件。
- 规范 §4.3：未实现解码时不得放置假视频占位。
- 裁决：一致，无冲突。MVP 视频页不出现预览区域；媒体组件接入后才显示，并标注为可选区域。

**C-04 状态语义词表**

- `ARCHITECTURE.md`：`Passed / Failed / Warning / Skipped / Unknown / Cancelled / TimedOut`（7 态，面向诊断步骤）。
- 规范 §4.8：待运行 / 准备中 / 运行中 / 已完成 / 部分成功 / 失败 / 已取消（面向任务）。
- 裁决：二者不冲突但需映射。实现时采用两层模型：任务层（含"部分成功"）与步骤层（含 `Skipped/Unknown`），并建立显式映射函数，禁止把 `Skipped` 渲染成 `Failed`。已记录为 ADR-016。

## 5. 风险清单

| 编号 | 风险 | 等级 | 影响 | 缓解 |
| --- | --- | --- | --- | --- |
| R-01 | 工作区非 Git 仓库 | 高 | 无法用 `git diff` 审查改动，回滚困难 | 建议先 `git init`（需用户确认）；否则每阶段手工备份 |
| R-02 | 厂商 SDK（海康/大华）许可、位数、再分发条款未确认 | 高 | 可能无法分发，或需重写适配层 | LF-012 前书面核验；在此之前不引入任何厂商二进制（ADR-011） |
| R-03 | FFmpeg 分发许可 | 中 | 商业分发合规风险 | MVP 不分发；如需，改用 LGPL 构建并登记（ADR-007） |
| R-04 | Pktmon/Npcap 需要管理员权限 | 中 | 安装体验与权限模型复杂 | 不做 MVP 强依赖（ADR-012） |
| R-05 | WPF-UI 4.3.0 为较新主版本 | 中 | 升级可能破坏样式 | 锁定版本；升级前回归壳层/表格/日志三页 |
| R-06 | 设计令牌与 WPF-UI 主题资源可能重叠 | 中 | 令牌被控件库默认值覆盖，导致样式不一致 | 令牌以 `Lf` 前缀语义命名，控件样式引用令牌而非库内键 |
| R-07 | 无 ARM64/Windows 10 早期版本验证环境 | 低 | 支持矩阵无法实测 | LF-013 前明确最低支持范围，不承诺未验证组合 |
| R-08 | `towerlens` 等外部资料可能含真实凭据 | 高 | 凭据泄漏进产品 | 复用前逐文件审查；只允许人工脱敏后的夹具入库 |
